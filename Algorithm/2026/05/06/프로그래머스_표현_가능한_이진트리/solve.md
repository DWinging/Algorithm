## 📌 문제 개요
주어진 십진수 숫자를 이진수로 변환했을 때, 해당 이진수가 **포화 이진트리(Full Binary Tree)**의 순회 결과로 표현될 수 있는지 판별하는 문제입니다.
*   **핵심 조건:** 더미 노드(0)를 부모로 가지는 자식 노드는 절대 일반 노드(1)가 될 수 없습니다. (부모가 0이면, 하위 서브트리는 모두 0이어야 함)

---

## 💡 풀이 핵심 (Core Logic)

### 1. 포화 이진트리 규격($2^n - 1$)의 역산
*   단순히 숫자를 표현하는 최소 비트 길이를 구하는 것이 아니라, **트리의 높이에 따른 전체 노드 수($1, 3, 7, 15, 31 \dots$)** 규격을 맞춰야 합니다.
*   **수식 적용:** 실제 숫자의 비트 길이를 구한 뒤, `tree_size = (tree_size + 1) * 2 - 1` 점화식을 통해 숫자를 포용할 수 있는 가장 작은 포화 이진트리의 크기를 산출합니다.

### 2. 비트 마스킹을 통한 O(1) 재귀 컷오프 (Subtree Validation)
*   일반적인 트리 탐색처럼 모든 자식 노드를 순회할 필요가 없습니다. 
*   **포인트:** 현재 서브트리의 루트 노드가 `0`일 때, 하위 서브트리 비트 전체를 담고 있는 변수 `number`가 `0`인지만 확인(`number == 0`)하면 됩니다. 이를 통해 불필요한 분기를 제거하고 검사 속도를 극대화합니다.

## 📊 설계 관점 비교: 문자열(String) vs 비트마스킹(Bitmasking)

무거운 라이브러리나 객체 생성 없이, 정수형 변수의 비트 조작만으로 트리를 분할 정복하는 구조적 차이입니다.

| 비교 항목 | String + 슬라이싱 | Pure Bitmasking (현재 풀이) |
| :--- | :--- | :--- |
| **자료 구조** | `std::string` | `long long` |
| **접근 방식** | 십진수 -> 이진수 문자열 변환 후 인덱싱 | 비트 시프트(`>>`) 및 마스킹(`&`) |
| **메모리 할당** | 재귀마다 문자열 `substr` 객체 동적 할당 | **추가 메모리 할당 없음 (Zero-Allocation)** |
| **Subtree 0 검사** | 반복문으로 `0`~`length`까지 `1` 탐색 | **`number == 0` 조건으로 $O(1)$ 즉시 판별** |
| **성능 최적화** | 오버헤드가 크고 속도 저하 발생 | **극한의 메모리 효율 및 연산 속도 보장** |

## 🛠 트러블 슈팅

### 1. 트리의 크기(비트 수) 산정 오류
*   **문제:** 초기에 변수의 비트 크기를 $1, 2, 3, 4 \dots$ 씩 선형적으로 증가시키며 탐색하려 했으나, 트리 구조의 루트 위치를 잡을 수 없는 문제 발생. (예: 2비트는 루트를 특정할 수 없음)
*   **해결:** 포화 이진트리의 특성에 맞추어, 비트 사이즈를 반드시 $2^n - 1$ 단위로 맞추어 트리의 완벽한 중앙(루트)을 보장하도록 사이즈 산출 로직을 교정했습니다.

### 2. 재귀 함수 기저 조건 누락
*   **문제:** 문제 로직 특성상 문제가 발생하지 않지만, 무한 루프 위험성을 내포하고 있음
*   **해결:** `if(bit_count <= 1) return 1;` 기저 조건을 추가하여 무한 루프 위험을 방지함
