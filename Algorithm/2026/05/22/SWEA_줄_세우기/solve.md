### SWEA 7991 [줄 세우기](https://swexpertacademy.com/main/code/problem/problemDetail.do?contestProbId=AWvQdg1KU3QDFASy) (c++, Java)

> **날짜:** 2026년 5월 22일 <br>
> **알고리즘:** 그리디, 정렬, 비둘기 집의 원리<br>
> **언어:**  c++, Java <br>
> **핵심 키워드:** 그리디, 정렬, 사전 순서

## 📌 문제 개요

* **핵심 요약**: $N$명의 학생들을 일렬로 줄 세울 때, 인접한 두 학생의 키가 연속된 자연수($a[i + 1] = a[i] + 1$)가 되지 않도록 배치하면서, 조건을 만족하는 조합 중 **사전 순으로 가장 앞선 수열**을 구하는 문제.
* **제약 조건**: 학생 수 $N$ ($1 \le N \le 5000$), 학생들의 키는 자연수.

---

## 💡 풀이 핵심 (Core Logic)

* **상태 압축 스캔 ($O(N)$):** 무거운 객체나 정렬 라이브러리 없이 정적 카운팅 배열(counts)만 활합니다. 이후 로직에서 중복 연산을 줄이고, 다음 위치를 빠르게 찾을 수 있습니다.
* **벼랑 끝 상태 판별:** 남은 원소 수($n$)가 num과 num + 1의 빈도 합과 같아지는 순간(counts[num] + counts[num + 1] == n), 더 이상 외부 완충재를 쓸 수 없는 비둘기 집의 원리 상태가 됩니다. 이때는 num + 1 을 모두 출력하고, num을 출력하면 됩니다.
* **완충재(Mercenary) 점프:** 현재 숫자(num) 연속을 끊어야 할 때, 뒤쪽 영역(num + 2 이상)에서 가장 작은 숫자를 하나만 배치하여 흐름을 유지합니다.

---

## 🚨 트러블 슈팅

### 후위 감소 연산자(--)가 남긴 유령 데이터 (-1)

* **현상:** "어차피 로직 안에서 원소 수만큼 다 털어 쓰니 알아서 0으로 수렴하겠지"라는 자가 치유(Self-Healing) 직관을 믿고 매 테케 초기화 로직을 제거했으나, 자바 버전에서만 무한 루프나 인덱스 에러 발생.
* **원인:** while(counts[num]-- > 0) 조건문 평가 특성상, 빈도가 0이 되었을 때도 0 > 0을 검사한 후  한 번 더 감소연산을 수행하여 최종적으로 **-1**이 남음.
* **결과:** 초기화가 없는 상태에서 다음 테스트케이스로 넘어가면, 새 입력 counts[num]++를 해봤자 -1 + 1 = 0이 되어 입력을 삼켜버림. 존재해야 할 숫자가 증발하여 탐색 함수(searchNextNum)의 정확도가 떨어짐
* **해결:** C++과 동일하게 매 테스트케이스 시작 시 안전하게 고정 SIZE 전체 초기화 루프를 복구하거나, 후위 연산 수식을 분리하여 정확히 0으로 수렴하게 교정.
