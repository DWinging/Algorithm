### SWEA D6 [영준이의 무게측정](https://swexpertacademy.com/main/code/problem/problemDetail.do?contestProbId=AV5LeQJqDpwDFAXc) (C++)

> **날짜:** 2026년 5월 5일 <br>
> **알고리즘:** Union-Find, 가중치 분리 집합 (Weighted DSU) <br>
> **언어:** C++, Java <br>
> **핵심 키워드:** 가중치 갱신 타이밍, 경로 압축, 수학적 역산

## 📌 문제 개요
양팔 저울을 사용해 두 샘플의 무게를 비교하고, 특정 두 샘플의 무게 차이를 구하는 문제입니다. 
*   `! a b w` : b가 a보다 w그램 무겁다는 의미 ($b - a = w$)
*   `? a b` : b가 a보다 얼마나 무거운지를 출력 (비교 불가 시 `UNKNOWN`)
*   핵심은 샘플의 '정확한 무게'가 아닌 **'루트 노드 기준의 상대적인 무게 격차'**를 동적으로 관리하는 것입니다.

---

## 💡 풀이 핵심 (Core Logic)

### 1. 가중치 갱신 방향성의 수학적 역산
*   `union(a, b, w)` 연산 시, 두 트리를 병합할 때 무게 밸런스를 유지하기 위한 수식을 도출해야 합니다.
*   **수식 도출:** $b$가 $a$보다 $w$ 무겁다는 조건($b - a = w$)을 기준으로, $pB$를 $pA$ 밑으로 종속시킬 때 두 루트 간의 차이는 **`diff[pB] = diff[a] - diff[b] + w`**가 됩니다. 이 역산을 통해 가중치 오염을 완벽히 방지합니다.

### 2. 스택(Stack) 역추적을 통한 경로 압축 (Top-Down)
*   일반적인 재귀 기반의 `find` 대신, 커스텀 스택 배열(`stack_arr`)을 활용하여 경로를 압축합니다.
*   **포인트:** 트리를 타고 올라가면서(Bottom-Up) 갱신하면 부모의 갱신이 완료되지 않아 누적합이 깨집니다. Root를 먼저 확실히 찾은 뒤, 스택에서 꺼내며 **내려오면서(Top-Down) 갱신**해야만 완벽한 가중치 동기화가 이루어집니다.

## 📊 설계 관점 비교: LCA vs Weighted Union-Find

초기 발상이었던 정적 트리 탐색(LCA)과 최종 해답(Union-Find)의 구조적 차이입니다.

| 비교 항목 | LCA (Lowest Common Ancestor) | Weighted Union-Find |
| :--- | :--- | :--- |
| **구조의 성격** | **정적 트리 (Static Tree)** | **동적 집합 (Dynamic Sets)** |
| **적합한 상황** | 트리의 연결 관계가 초기에 고정되어 있을 때 | 쿼리에 따라 실시간으로 노드들이 합쳐질 때 |
| **핵심 기법** | `depth` 배열 및 공통 조상 탐색 | `find` 시 **스택 기반 경로 압축** |
| **거리 계산 방식**| 공통 조상으로부터의 누적 합 활용 | 루트 노드와의 상대적 격차(`diff`) 누적 |
| **이 문제에서의 한계** | 집합이 병합될 때마다 `depth` 갱신 불가 | 트리의 높이를 강제로 무시하며 $O(1)$에 가깝게 산출 |

## 🧠 회고 및 결론

1.  **LCA 발상의 전환:** "두 지점 간의 거리를 잰다"는 발상 때문에 처음에는 LCA를 떠올렸으나, 실시간으로 집합이 합쳐지는 동적 환경에서는 **Weighted Union-Find**가 구조적으로 훨씬 적합하다는 것을 깊이 체감했습니다.
2.  **트러블 슈팅의 중요성:** 경로 압축 시 가중치를 누적하는 '타이밍(Top-Down vs Bottom-Up)'이 전체 로직의 정합성을 좌우한다는 것을 깨달았습니다.
