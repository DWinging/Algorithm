## 📌 문제 개요

빈 영어사전에 단어를 추가(`insert`)하고, 특정 문자열로 시작하는 단어의 개수를 실시간으로 확인(`query`)하는 시스템 구현 문제입니다.

* **주요 과제:** 단어가 추가됨에 따라 변화하는 접두사(Prefix)의 빈도수를 실시간으로 관리해야 함.
* **성능 요구:** 수많은 단어 추가와 쿼리가 동시에 일어나므로, $O(단어 길이)$ 수준의 빠른 탐색 성능이 필수적임.


---

## 💡 풀이 핵심 (Core Logic)

* **2차원 정적 배열 기반 Trie:** `trie[MAX_NODE][26]` 배열을 선언하여, 각 노드에서 다음 알파벳으로 이동하는 경로를 인덱스 참조($O(1)$)로 즉시 찾아가도록 설계했습니다.
  
* **실시간 접두사 카운팅:** 단어를 삽입할 때 트리를 내려가면서 거쳐가는 모든 노드의 `count` 값을 `+1` 해줍니다. 이렇게 하면 `query` 시 해당 접두사의 마지막 노드에 저장된 값을 읽기만 하면 됩니다.

---

## 🛠 성능 최적화 인사이트 (Performance Insights)

* **초기화 범위 최적화 (가장 중요):** 테스트 케이스가 바뀔 때마다 백만 개 이상의 배열 전체를 초기화하면 시간 초과가 발생합니다. `total`(현재까지 사용된 노드 번호) 변수를 유지하고, **딱 사용했던 인덱스까지만 루프를 돌며 초기화**하여 오버헤드를 최소화했습니다.
  
* **입력 속도 최적화:** `String.charAt()`을 반복 호출하는 대신, 필요한 경우 `toCharArray()`를 루프 밖에서 한 번만 수행하여 내부적인 범위 체크 비용을 줄였습니다.

## 🧠 회고 및 결론

전형적인 트라이 문제로, 문제 지문에도 트라이를 권장하고 있다. 그래서 배열 기반의 트라이를 사용하며 문제를 해결하였지만, 메모리 낭비가 심해 비효율적인 코드를 작성하였다. 2차원 배열이 아닌 HashMap을 사용한 객체 기반 트라이를 구현하면, 메모리 사용량은 줄어들지만, 시간이 증가한다. 

따라서 이 문제에서 메모리와 시간 효율을 모두 챙기기 위해서는 연결 리스트 기반의 LCRS 방식을 구현해야하며 이 부분은 아직 학습하는 중이다. 따라서 다음에 적용해볼 예정이다.
