### Codeforces 1547E [Air Conditioner](https://codeforces.com/problemset/problem/1547/E) (Java)

> **날짜:** 2026년 9월 1일 <br>
> **알고리즘:** 다익스트라, DP<br>
> **언어:**  Java <br>
> **핵심 키워드:** 다익스트라, DP

## 📌 문제 개요

* 길이 `n`의 일렬로 배치된 공간에 `k`개의 에어컨이 존재한다.
* `i`번째 에어컨은 `a_i`번 위치에 설치되어 있으며, 설정 온도는 `t_i`이다.
* 각 위치 `i`의 온도는 모든 에어컨이 해당 위치에 미치는 온도 중 최솟값으로 결정된다.
* 에어컨 `j`가 위치 `i`에 미치는 온도는 다음과 같다.

```text
t_j + |a_j - i|
```

* 따라서 각 위치의 최종 온도는 다음 식으로 계산할 수 있다.

```text
min(t_j + |a_j - i|)
```

* 모든 테스트 케이스에 대해 `n`의 합이 `3 × 10^5` 이하이므로, 각 위치를 효율적으로 처리하는 방법이 필요하다.

---

## 💡 풀이 핵심 (Core Logic)

### 1. 각 에어컨의 온도는 거리에 따라 1씩 증가한다

에어컨이 설치된 위치의 온도는 설정 온도 `t_i`이며, 해당 위치에서 한 칸 멀어질 때마다 영향을 주는 온도는 `1`씩 증가한다.

```text
에어컨 위치 : t
거리 1      : t + 1
거리 2      : t + 2
거리 3      : t + 3
```

따라서 문제는 여러 위치에서 시작한 값이 좌우로 `+1`씩 증가하며 전파될 때, 각 위치에서 얻을 수 있는 최솟값을 계산하는 문제로 해석할 수 있다.

---

### 2. 오른쪽에서 전달되는 최소 온도를 먼저 반영한다

배열을 오른쪽에서 왼쪽으로 탐색한다.

현재 위치 `i`에서 오른쪽 위치 `i + 1`의 최소 온도를 알고 있다면, 오른쪽에서 현재 위치까지 전달되는 온도는 `arr[i + 1] + 1`이다.

따라서 현재 저장된 값과 비교하여 더 작은 값을 선택한다.

```text
arr[i] = min(arr[i], arr[i + 1] + 1)
```

이를 통해 각 위치에 대해 오른쪽에 존재하는 에어컨들이 전달할 수 있는 최소 온도가 반영된다.

---

### 3. 왼쪽에서 전달되는 최소 온도를 추가로 반영한다

이번에는 배열을 왼쪽에서 오른쪽으로 탐색한다.

왼쪽 위치 `i - 1`의 최소 온도를 알고 있다면, 왼쪽에서 현재 위치까지 전달되는 온도는 `arr[i - 1] + 1`이다.

```text
arr[i] = min(arr[i], arr[i - 1] + 1)
```

첫 번째 탐색에서 오른쪽 방향의 최솟값이 이미 반영되어 있으므로, 두 번째 탐색에서는 왼쪽 방향에서 전달되는 값과 비교하기만 하면 된다.

---

### 4. 양방향 탐색으로 모든 에어컨의 영향을 계산할 수 있다

어떤 위치 `i`에 영향을 주는 에어컨은 반드시 `i`의 왼쪽 또는 오른쪽에 존재한다.

따라서

```text
오른쪽 → 왼쪽 탐색
→ 오른쪽 에어컨의 영향 반영

왼쪽 → 오른쪽 탐색
→ 왼쪽 에어컨의 영향 반영
```

두 번의 선형 탐색만으로 모든 에어컨에 대한 최솟값을 계산할 수 있다.

각 위치를 두 번씩만 확인하므로 시간 복잡도는 `O(n)`이다.

---

**핵심은 각 에어컨에서 발생하는 온도가 거리에 따라 1씩 증가한다는 점을 이용하여, 오른쪽과 왼쪽에서 전달되는 최소 온도를 각각 한 번씩 반영하는 것이다.**

## 📊 풀이 방식 비교 (Dijkstra vs DP)

| 구분      | 멀티소스 다익스트라                           | 양방향 DP                                 |
| ------- | ------------------------------------ | -------------------------------------- |
| 문제 해석   | 각 위치를 정점으로 보고 인접 위치 이동 비용을 `1`로 설정   | 일렬로 배치된 배열에서 인접 위치의 최솟값을 전파            |
| 시작점     | 모든 에어컨 위치를 시작점으로 설정                  | 에어컨 위치에 설정 온도를 기록                      |
| 값 전파    | PriorityQueue를 이용해 작은 온도부터 좌우로 확장    | 오른쪽→왼쪽, 왼쪽→오른쪽으로 각각 한 번 탐색             |
| 갱신 방식   | `dist[next] > dist[cur] + 1`이면 갱신    | `arr[i] = min(arr[i], arr[i ± 1] + 1)` |
| 시간 복잡도  | `O(n log n)`                         | `O(n)`                                 |
| 추가 자료구조 | PriorityQueue 필요                     | 별도의 자료구조 불필요                           |
| 장점      | 일반적인 최단거리 문제로 쉽게 모델링 가능              | 문제의 1차원 구조를 활용하여 구현과 연산이 단순함           |
| 단점      | PriorityQueue 연산 및 객체 생성에 따른 오버헤드 존재 | 선형 구조와 일정한 증가량을 이용할 수 있는 문제에 한정됨       |
| 최종 선택   | 적용 가능                                | 문제 구조에 가장 적합                           |

멀티소스 다익스트라를 사용하면 각 에어컨을 서로 다른 초기 거리를 가지는 시작점으로 설정하여 최단거리 문제처럼 해결할 수 있다.

하지만 본 문제에서는 모든 위치가 일렬로 연결되어 있고, 한 칸 이동할 때 온도가 항상 정확히 `1`씩 증가한다.

따라서 PriorityQueue를 이용해 탐색 순서를 관리할 필요 없이, 양방향으로 배열을 한 번씩 탐색하는 것만으로 동일한 결과를 얻을 수 있다.

결과적으로 다익스트라의 `O(n log n)` 시간 복잡도를 양방향 DP를 통해 `O(n)`으로 단축할 수 있으며, 구현 또한 더 단순해진다.

## 🧠 회고 및 결론

문제를 처음 봤을 때 익숙한 다익스트라 풀이를 먼저 떠올렸다. 일차원 배열에서 특정 위치를 기준으로 양옆으로 값이 퍼지는 최단거리 유형을 이전에 풀어본 경험이 있었기 때문이다.

DP 풀이 역시 비슷한 아이디어를 사용한 문제를 풀어본 적은 있었지만, 처음부터 떠올리지는 못했다. 아직은 그래프 형태로 먼저 해석하는 것이 더 익숙하고, 배열의 구조를 이용해 탐색을 줄이는 DP 관점은 조금 더 익숙해질 필요가 있는 것 같다.
