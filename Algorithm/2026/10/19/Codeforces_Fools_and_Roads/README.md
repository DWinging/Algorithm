### Codeforces 1900 [Fools and Roads](https://codeforces.com/problemset/problem/191/C) (Java)

> **문제 번호:** 191C <br>
> **날짜:** 2026년 10월 19일 <br>
> **알고리즘:** 트리, LCA, BFS, 자료구조 <br>
> **언어:** Java <br>
> **핵심 키워드:** 트리, LCA, BFS, 이진리프팅, 후위순회, 차분 배열 트릭

## 📌 문제 개요

- `n`개의 도시와 `n - 1`개의 양방향 도로가 트리를 이룬다 (`2 ≤ n ≤ 100,000`).
- 이동 경로 `k`개가 각각 출발 도시와 도착 도시의 쌍으로 주어진다 (`0 ≤ k ≤ 100,000`).
- 각 이동은 두 도시 사이의 유일한 단순 경로를 따른다.
- 각 도로를 지나는 이동의 수를 도로가 입력된 순서대로 구한다.

---

## 💡 풀이 핵심 (Core Logic)

### 1. 도로의 입력 순서를 보존한 그래프 구성

`buildGraph`는 양방향 인접 리스트에 이웃 도시와 도로의 입력 인덱스를 함께 저장한다. 트리를 탐색하는 순서와 도로의 입력 순서는 다르므로, 이 인덱스로 최종 결과를 원래 도로 순서에 맞춰 기록한다.

### 2. BFS로 깊이와 이진리프팅 테이블 구성

`buildParentTable`은 1번 도시를 루트로 BFS를 수행하며 각 도시의 깊이와 직속 부모를 기록한다. 부모가 자식보다 먼저 처리되므로 `parents[k][v] = parents[k - 1][parents[k - 1][v]]`로 `2^k`번째 조상까지 바로 채울 수 있다. 이 테이블은 이후 LCA를 구할 때 부모를 한 칸씩 따라가지 않고 여러 단계씩 이동하는 데 사용한다.

BFS 큐 `que`에는 부모, 현재 도시, 부모와 연결된 도로 인덱스를 저장하고 탐색 이후에도 유지한다. 이 방문 순서는 마지막 단계에서 자식의 값을 부모에게 누적하는 데 재사용한다.

### 3. LCA를 찾아 경로의 차분 표시

`findLca`는 깊이 차이의 비트에 맞춰 깊은 도시를 올려 두 도시의 깊이를 맞춘다. 두 도시가 같아지면 그 도시를 반환하고, 다르면 큰 조상 간격부터 확인하며 조상이 서로 다른 동안 두 도시를 함께 올린다. 마지막에 두 도시의 공통 부모가 LCA가 된다.

`markPaths`는 각 경로 `(u, v)`에 대해 `cnt[u]++`, `cnt[v]++`, `cnt[lca] -= 2`를 수행한다. 양 끝점에서 시작한 값을 부모 방향으로 모으되 LCA에서 상쇄하여, 실제 경로에 없는 LCA 위쪽 도로에는 값이 전달되지 않도록 한다. 따라서 경로에 포함된 도로를 매번 직접 방문할 필요가 없다.

### 4. BFS 역순 누적으로 도로별 통과 횟수 계산

`countEdgeUsage`는 `que`를 끝에서부터 루트 직전까지 순회한다. BFS 역순에서는 모든 자식이 부모보다 먼저 처리되므로, 재귀 후위순회 없이도 자식 서브트리의 값을 먼저 합칠 수 있다.

현재 도시 `v`에 모인 `cnt[v]`는 해당 서브트리와 바깥을 연결하는 부모 도로를 지나는 경로 수다. 이를 `res[edge]`에 더하고 `cnt[p]`에도 누적하여 상위 도로의 계산에 반영한다. 마지막으로 `formatResult`가 도로의 입력 순서대로 결과를 문자열로 만든다.

### 시간 복잡도

그래프 구성과 역순 누적, 결과 출력은 각각 `O(n)`이다. 조상 테이블 구성에 `O(n × LOG)`, 각 경로의 LCA 계산에 `O(LOG)`가 필요하므로 전체 시간 복잡도는 `O((n + m) × LOG)`이다. 코드에서는 `LOG = 18`로 고정하며, 노드 수에 맞춰 조상 테이블 높이를 표현하면 `O((n + m) log n)`이다.

- `n`: 도시 수
- `m`: 코드에서 사용하는 이동 경로 수 (문제의 `k`)
- `LOG`: 조상 테이블의 높이 (코드에서는 18)
