### SWEA 9780 [외계인 침공](https://swexpertacademy.com/main/code/problem/problemDetail.do?contestProbId=AXE0gpIa3dADFAVX) (Java, c++)

> **날짜:** 2026년 6월 17일 <br>
> **알고리즘:** DP <br>
> **언어:**  Java, c++ <br>
> **핵심 키워드:** DP, 메모리 관리(Java)

## 📌 문제 개요

* **초기 상태:** 선형 대로를 따라 $1$번부터 $N$번까지 순서대로 배치된 $N$개의 도시가 주어지며($1 \le N \le 10^6$), 각 도시에는 $A_i$명의 개구리가 거주하고 있다($0 \le A_i \le 10^9$).
* **침공 및 소식 전파 메커니즘:** 하루 오후에 최대 한 도시를 침공하여 개구리를 전원 납치할 수 있다. 침공당한 도시 $i$는 다음 날 아침 양 옆의 도시($i-1, i+1$)로 소식을 전파한 뒤 즉시 황폐화되어 물리적으로 격리된다. 소식은 황폐화되지 않은 도시를 거쳐 매일 한 칸씩 양방향으로 전파된다.
* **대피 제약 조건:** 소식을 전달받은 도시의 개구리들은 당일 아침 즉시 방공호로 대피한다. 소식 전파 이후(침공 다음 날부터) 해당 도시를 침공하는 경우 개구리를 납치할 수 없다.
* **목표:** 도시 간의 소식 전파 및 대피 시스템의 상호작용 속에서 납치할 수 있는 개구리 수의 최댓값을 산출한다.

---

## 💡 풀이 핵심 (Core Logic)

* **상태 공간 압축:** 소식 전파 및 황폐화 조건은 "임의의 도시 $i$를 침공하면 인접한 도시 $i-1$과 $i+1$은 선택할 수 없다"는 제약 조건으로 귀결된다. 연속된 두 도시를 선택할 경우, 먼저 침공당한 도시의 소식이 익일 아침 인접 도시로 전파되어 대피가 완료되기 때문이다. 따라서 해당 문제는 선형 배열에서 인접하지 않은 원소들을 선택하여 합을 최대화하는 1차원 다이나믹 프로그래밍(DP) 구조로 환원된다.
* **결정 상태에 따른 점화식 설계:** 각 도시의 상태를 '현재 도시를 침공하는 경우'와 '침공하지 않는 경우'의 2가지 레이어로 분리하여 독립적인 가치를 누적한다.
* `pre1` (현재 도시를 침공함): 이전 도시를 침공하지 않아야 하므로, 이전 도시를 선택하지 않은 상태에 현재 개구리 수를 합산한다. ($\text{target1} = \text{pre2} + \text{val}$)
* `pre2` (현재 도시를 침공하지 않음): 이전 도시의 침공 여부와 무관하게 누적된 가치의 최댓값을 승계하며, 현재 도시의 값은 합산하지 않는다. ($\text{target2} = \max(\text{pre1}, \text{pre2})$)

## 🛠 성능 최적화 인사이트 (Performance Insights)

* **공간 복잡도 최적화 ($O(N) \rightarrow O(1)$):** $N$이 최대 $1,000,000$인 조건에서 `long dp[1000000][2]`와 같은 대형 배열을 매 테스트 케이스마다 할당하면 메모리 사용량 증가 및 가비지 컬렉션(GC) 부하로 인해 TLE(시간 초과) 또는 MLE(메모리 초과)가 발생한다. 점화식이 직전 단계($i-1$)의 데이터만을 참조하므로, 배열을 배제하고 2개의 `long long` 변수(`pre1`, `pre2`)만을 활용하여 공간 복잡도를 최적화한다.
* **단일 루프 스트림 프로세싱 (Single Pass):** 입력을 배열에 저장한 후 재순회하는 방식 대신, 표준 입력 스트림에서 정수를 읽어옴과 동시에 DP 연산을 수행하여 변수를 갱신하는 단일 루프 파이프라인을 구축한다. C++의 경우 `ios::sync_with_stdio(false); cin.tie(NULL);` 설정을 통해 내부 버퍼링을 최적화하고, 메모리(DRAM) 참조 오버헤드를 줄여 연산 속도를 극대화한다.

## 🧠 회고 및 결론

전형적인 DP 유형이지만, 의외로 BufferedReader를 사용하고 배열을 만들어 정석으로 풀 경우 메모리 초과가 발생하는 재밌는 문제다. BufferedReader를 사용하게 되면 String 객체를 생성하는 비용이 발생하고, 도시의 수가 1,000,000에 결과값 저장용으로 long 타입을 사용하다보니 정석 풀이를 사용할 경우 메모리 초과가 발생한다.

그래서 이 문제는 Java의 경우 메모리 관리에 대한 조율이 필요한 문제라 Java로 풀 때 메모리 관리에 대해 고민하게 되는 좋은 문제다.
