### BaekJoon Gold Ⅱ [도토리 숨기기](https://www.acmicpc.net/problem/15732) (Java)

> **문제 번호:** 15732 <br>
> **날짜:** 2026년 11월 28일 <br>
> **알고리즘:** 이분 탐색, 파라매트릭 서치 <br>
> **언어:** Java <br>
> **핵심 키워드:** 파라매트릭 서치

## 📌 문제 개요

- `1`번부터 `N`번까지의 상자와 `K`개의 도토리 배치 규칙이 주어진다.
- 각 규칙 `(A, B, C)`는 `A`번부터 `B`번까지 `C` 간격으로 도토리를 하나씩 추가한다.
- 여러 규칙이 같은 상자를 지정하면 해당 상자에 도토리가 중복해서 들어가며, 상자별 용량 제한은 없다.
- `1 ≤ N ≤ 1,000,000`, `1 ≤ K ≤ 10,000`, `1 ≤ D ≤ 1,000,000,000`이며, 모든 규칙으로 배치할 수 있는 도토리의 총수는 `D` 이상이다.
- 규칙에 따라 앞 번호 상자부터 `D`개의 도토리를 채울 때, 마지막 도토리가 들어가는 상자의 번호를 구한다.

---

## 💡 풀이 핵심 (Core Logic)

### 1. 규칙별 개수 계산으로 누적 도토리 수 판정

입력받은 규칙을 `rules`에 저장하고, `solve`에서 `target`번 상자까지 넣을 수 있는 도토리 수를 계산한다. 각 규칙의 시작 상자 `A`가 `target`보다 크면 해당 구간에는 도토리가 없으므로 건너뛴다.

그 외에는 마지막으로 셀 수 있는 범위를 `temp = min(target, B)`로 제한하고, `(temp - A) / C + 1`을 더한다. 이는 첫 상자 `A`를 포함한 등차수열의 항 개수이며, 상자를 하나씩 순회하지 않고 규칙 하나를 상수 시간에 계산하기 위한 처리다. 규칙이 겹친 상자에도 도토리가 각각 추가되므로 규칙별 개수를 그대로 합산한다.

누적값 `cnt`는 `D`보다 커질 수 있으므로 `long`으로 저장한다. 모든 규칙을 확인한 뒤 `cnt >= d`를 반환하여, 해당 상자까지 마지막 도토리를 배치할 수 있는지 판정한다.

### 2. 이분 탐색으로 조건을 만족하는 최소 상자 탐색

상자 번호가 커져도 누적 도토리 수는 줄어들지 않으므로, `solve`의 결과는 어느 지점부터 계속 참이 된다. 따라서 마지막 도토리가 들어가는 상자는 누적 개수가 `D` 이상이 되는 최초의 상자다.

`binarySearch`는 `left = 0`, `right = n`에서 시작한다. 중간값 `mid`가 조건을 만족하면 `res = mid`로 후보를 저장하고 `right = mid - 1`로 줄여 더 앞선 상자가 가능한지 찾는다. 만족하지 않으면 앞쪽 상자만으로는 도토리가 부족하므로 `left = mid + 1`로 옮긴다.

`0`번까지의 누적 개수는 `0`이므로 `D ≥ 1`에서 조건을 만족하지 않는다. 전체 규칙의 도토리 수가 `D` 이상이라는 보장에 따라 유효한 후보를 찾을 수 있으며, 탐색이 끝나면 저장된 최소 후보 `res`를 출력한다.

### 시간 복잡도

`solve`는 모든 규칙을 확인하므로 한 번에 `O(K)`가 걸린다. 이분 탐색에서 이를 `O(log N)`번 호출하므로 전체 시간 복잡도는 `O(K log N)`이다. 규칙 배열을 저장하는 공간 복잡도는 `O(K)`이다.

- `N`: 상자의 개수
- `K`: 규칙의 개수
